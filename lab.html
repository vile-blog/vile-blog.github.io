The LabPhòng thí nghiệm

Three tiny distributed systems running right here in your browser. Break them on purpose — crash nodes, cut the network, add servers, tune quorums — and watch what the Designing Data-Intensive Applications chapters actually mean in practice.Ba hệ thống phân tán thu nhỏ chạy ngay trong trình duyệt của bạn. Cứ phá chúng đi — làm sập node, cắt mạng, thêm server, chỉnh quorum — rồi xem các chương của Designing Data-Intensive Applications thực sự có nghĩa gì.

01 · consensusđồng thuận

Raft: elect a leader, survive a partitionRaft: bầu leader, sống sót qua phân vùng mạng

Five nodes. Followers wait for heartbeats; if the leader goes quiet, a randomised timer fires and a candidate asks for votes. Click a node to inspect it (and crash or revive it), split the network to create two isolated sides, then try to write — only a side holding a majority can commit. (DDIA ch. 9)Năm node. Follower chờ heartbeat; nếu leader im lặng, một bộ đếm ngẫu nhiên nổ và một candidate đi xin phiếu. Bấm vào node để xem chi tiết (và làm sập hoặc hồi sinh nó), chia đôi mạng để tạo hai phía bị cô lập, rồi thử ghi — chỉ phía có đa số mới commit được. (DDIA ch. 9)

    02 · partitioningphân mảnh

    Consistent hashing: add a server, move almost nothingConsistent hashing: thêm server, hầu như không phải di chuyển gì

    300 keys are hashed onto a ring; each belongs to the next server clockwise. Add or remove a server and see how few keys move — compared with naïve hash(key) mod N, which reshuffles almost everything. Crank up virtual nodes to even out the load, and click a server or a key to inspect it. (DDIA ch. 6)300 key được băm lên một vòng tròn; mỗi key thuộc về server đầu tiên theo chiều kim đồng hồ. Thêm hoặc bớt server rồi xem có bao nhiêu key phải chuyển — so với cách hash(key) mod N ngây thơ, vốn xáo trộn gần như tất cả. Tăng virtual node để cân bằng tải, và bấm vào server hay một key để xem chi tiết. (DDIA ch. 6)

    03 · replicationsao chép

    Quorums: when does a read see the latest write?Quorum: khi nào một lần đọc thấy bản ghi mới nhất?

    A write waits for W of N replicas; a read asks R. If W + R > N the two sets must overlap, so the read can't miss the newest value. Otherwise it might. Click a replica to crash it. Write, read, then hit Run 500 trials to measure the real stale-read rate against the maths. (DDIA ch. 5)Một lần ghi chờ W trong N replica; một lần đọc hỏi R replica. Nếu W + R > N thì hai tập buộc phải giao nhau, nên lần đọc không thể bỏ lỡ giá trị mới nhất. Ngược lại thì có thể. Bấm vào replica để làm sập nó. Hãy ghi, đọc, rồi bấm Chạy 500 lần thử để đo tỉ lệ đọc dữ liệu cũ thực tế so với công thức. (DDIA ch. 5)
